# RUNBOOK.md: день воркшопа

Для ведущего табло и ведущих за столами. Сетап сделан по `SETUP.md`,
генеральный прогон пройден.

## Формат коротко

- 7 команд по 3 человека, ведущий на каждом столе. 3 часа, три этапа, на
  каждый этап своя фича.
- Команда = банк из трех блоков: `retail` (мобильный банк клиента), `cib`
  (продукты и решения), `backend` (данные клиентов). У каждого участника
  один блок и свой агент, Claude Code или Codex.
- Ролей по именам нет. Участник сам выбирает команду (номер стола) и блок в
  установщике ноутбука. Между этапами блоками можно поменяться: сохранить
  работу, запустить установщик еще раз, выбрать другой блок.
- Соседний блок агент видит только через его `CONTRACT.md`. Другие команды
  не видны совсем: у каждой свой репозиторий.
- Участник просит агента сохранить работу. Через 2-4 минуты блок пересобран
  на Render.
- Симулятор раз в 30 секунд замечает новую сборку, LLM-судья оценивает банк
  команды целиком, база клиентов растет или падает. Старт у всех 500.

## Пульт

Одни и те же команды тремя способами:

1. Сайт GitHub, работает и из корпоративной сети: оркестратор на GitHub,
   Actions, Workshop ops, Run workflow, выбрать `command`. Результат в
   Summary рана.
2. Терминал с gh: `tools/setup/ops.sh <команда>`.
3. Терминал вне корпоративной сети: `python3 tools/setup/render_ops.py <команда>`.

| Что нужно | command на GitHub | в терминале |
|---|---|---|
| счет команд и последние события | `sim-state` | `sim state` |
| начать воркшоп: всем 500, опрос включен | `sim-start` | `sim start` |
| заморозить табло | `sim-stop` | `sim stop` |
| пересчитать сейчас, не ждать опроса | `sim-evaluate` | `sim evaluate` |
| здоровье всех сервисов | `status` | `status` |
| пересобрать блок команды: номер стола и блок | `deploy`, args `3:cib` | `deploy 3:cib` |

Табло: `https://<RENDER_PREFIX>-simulator.onrender.com` открывается из сети,
где *.onrender.com не закрыт: ноутбуки воркшопа, сеть площадки. Из сети банка
то же табло через прокси: `https://simulator.<поддомен>.workers.dev`. Оба
адреса в `TEAM.md` любой команды, все прокси печатает
`python3 tools/setup/cf_proxy.py urls`. Кнопка «Начать воркшоп» на табло
делает то же, что `sim-start`, и просит `ADMIN_TOKEN`. Токен хранит
организатор в `workshop.env`, ведущему табло передает лично.

## Сценарий

| Время | Что | Кто |
|---|---|---|
| за 30 мин | `status`: все 200. `sim-state`: воркшоп не идет. Табло на экране | ведущий табло |
| за 30 мин | на каждом ноутбуке пройден установщик: команда = номер стола, блок, имя. Репозиторий команды открыт в Claude или Codex | ведущие столов |
| 0:00 | участник пишет агенту «привет», агент проводит онбординг | участники |
| 0:15 | правила вслух: три блока, контракт, сохранение, табло, три этапа. Объявить фичу этапа 1 | ведущий табло |
| 0:20 | `sim-start` | ведущий табло |
| 0:20-1:05 | этап 1 | команды |
| 1:05 | разбор табло по ленте событий: у кого выросло и за что. Объявить фичу этапа 2 | ведущий табло |
| 1:10-1:55 | этап 2 | команды |
| 1:55 | разбор табло. Объявить фичу этапа 3 | ведущий табло |
| 2:00-2:40 | этап 3 | команды |
| 2:40 | `sim-stop`, табло замерло, скриншот | ведущий табло |

Время внутри рекомендация. Жесткое правило одно: пока не было `sim-start`,
сохранения клиентов не двигают. Между этапами табло не останавливать: счет
копится весь день, `sim-start` один раз.

## Какие фичи объявлять

Судья засчитывает любую осмысленную фичу. Больше клиентов приносит фича,
которая:

- видна клиенту в retail;
- проходит через все три блока;
- записана в `CONTRACT.md` блоков заголовками `### METHOD /path` и реально
  отвечает: судья сам вызывает объявленные ручки;
- не ломает то, что было. Сломанный перевод денег штрафуется кодом и стоит
  дороже новой фичи.

Этап 1, проверен прогоном: потребительский кредит. Клиент подает заявку в
retail, cib решает и объясняет отказ, backend хранит заявки.

Этап 2, не проверен прогоном: вклад. Открыть в retail, условия и ставка в
cib, хранение в backend.

Этап 3, не проверен прогоном: кэшбэк (категории в cib, начисления в
backend, экран в retail) или своя фича команды. Судья засчитает любую,
лишь бы проходила через три блока.

## Ведущему за столом

- Команда из двух человек: третий блок берет ведущий на запасном ноутбуке.
- В начале пусть договорятся голосом, кто какую ручку делает, и попросят
  агентов записать ручки в `CONTRACT.md`.
- Сохраняться маленькими шагами: каждое сохранение это сборка и оценка.
- Табло мигает вниз перед ростом: блоки выезжают не одновременно, это
  нормально.
- Агент отказывается лезть в чужой блок: так задумано.
- Код за участников не писать, помогать формулировать просьбы агенту.

## Если сломалось

| Симптом | Что делать |
|---|---|
| сохранение: `Permission denied (publickey)` | на репозитории команды нет deploy key: организатор запускает `tools/setup/github-access.sh keys` |
| сохранение висит | агент сам переводит SSH на ssh.github.com:443, это в его инструкции. Не помогло: сеть режет ssh.github.com:443 |
| сохранено, блок не обновился за 5 минут | репозиторий команды на GitHub, Actions, Deploy services via Render API. Notice «нет переменной RENDER_SID»: `github-access.sh render`. Красный run: открыть лог. Зеленый: `status` |
| в `status` деплой `build_failed` | Render, сервис, Logs: текст ошибки отдать агенту участника, он чинит свой блок и сохраняет снова |
| табло стоит | `sim-state`: воркшоп идет ? Нет: `sim-start`. Идет: `sim-evaluate` |
| объяснения в ленте короткие и однотипные | LLM не отвечает, проверить баланс ключа. Симулятор в это время считает запасной формулой и не встает |
| симулятор не открывается | `status`, затем `deploy sim`. Счет лежит в Postgres и переживает перезапуск |
| команда все сломала и хочет начать заново | только по просьбе команды: `tools/setup/sync-team-repos.sh <буква>` вернет ее репозиторий к старту, работа команды уйдет из main |

## Ручки правил

Меняются через `SIM_ENV` в `tools/setup/teams.conf`, потом `env`: симулятор
перезапустится, счет сохранится. Для ops.sh сначала закоммитить и запушить
teams.conf.

- `STAGNATION_RATE_PER_MIN`: утечка клиентов при простое, в teams.conf 0.
- `REGRESSION_COST`, `BROKEN_ENDPOINT_COST`, `UNREACHABLE_BLOCK_COST`: штрафы
  за поломки, по умолчанию 120, 60 и 90 клиентов.
- `CEIL`: потолок базы, в teams.conf 10000.

Полный список в `ORGANIZER.md`.

## После воркшопа

1. `sim-stop`, скриншот табло.
2. `tools/setup/github-access.sh revoke`: снять deploy keys и RENDER_API_KEY
   у команд.
3. В тот же день `suspend`: остановленные сервисы Render не тарифицирует.
4. После разбора `teardown` с подтверждением DELETE: удалить сервисы и базу.
5. Человек удаляет API-ключ Render и LLM-ключ.
6. Репозитории команд оставить на память или сбросить `sync-team-repos.sh`.
