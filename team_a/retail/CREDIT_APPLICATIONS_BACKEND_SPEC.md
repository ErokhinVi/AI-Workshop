# Спека для backend: сохранение кредитных заявок

## Сценарий retail

В мобильном банке появляется раздел "Персональный лимит". Клиент выбирает сумму
и срок, получает решение и объяснение. После этого retail должен сохранить
результат заявки в backend и уметь показать историю заявок клиента.

## Что нужно добавить в backend

### 1. Сохранить кредитную заявку

`POST /credit-applications`

Запрос:

```json
{
  "client_id": "c-01025",
  "amount_rub": 500000,
  "term_months": 24,
  "status": "approved",
  "approved_amount_rub": 500000,
  "rate_pct": 15.2,
  "monthly_payment_rub": 24200,
  "explanation": "Доход и кредитный профиль позволяют предложить эту сумму."
}
```

Поля:

| Поле | Тип | Обязательное | Описание |
|---|---:|---:|---|
| `client_id` | string | да | ID клиента из backend |
| `amount_rub` | integer | да | Запрошенная сумма |
| `term_months` | integer | да | Срок: 12, 24, 36, 48 или 60 месяцев |
| `status` | string | да | `approved`, `counter_offer` или `declined` |
| `approved_amount_rub` | integer | нет | Одобренная сумма. Для отказа можно `0` |
| `rate_pct` | number | нет | Ставка в процентах годовых |
| `monthly_payment_rub` | integer | нет | Ежемесячный платеж |
| `explanation` | string | да | Текст для клиента простым языком |

Ответ `200`:

```json
{
  "application_id": "ca-000001",
  "client_id": "c-01025",
  "amount_rub": 500000,
  "term_months": 24,
  "status": "approved",
  "approved_amount_rub": 500000,
  "rate_pct": 15.2,
  "monthly_payment_rub": 24200,
  "explanation": "Доход и кредитный профиль позволяют предложить эту сумму.",
  "created_at": "2026-05-25T13:55:00"
}
```

Ошибки:

| Код | Когда |
|---:|---|
| `400` | Некорректная сумма, срок или статус |
| `404` | Клиент не найден |

### 2. Получить историю заявок клиента

`GET /credit-applications/{client_id}`

Ответ `200`:

```json
{
  "client_id": "c-01025",
  "total": 1,
  "items": [
    {
      "application_id": "ca-000001",
      "client_id": "c-01025",
      "amount_rub": 500000,
      "term_months": 24,
      "status": "approved",
      "approved_amount_rub": 500000,
      "rate_pct": 15.2,
      "monthly_payment_rub": 24200,
      "explanation": "Доход и кредитный профиль позволяют предложить эту сумму.",
      "created_at": "2026-05-25T13:55:00"
    }
  ]
}
```

Требование: самые свежие заявки должны идти первыми.

Ошибка:

| Код | Когда |
|---:|---|
| `404` | Клиент не найден |

## Минимальные правила приема и сохранения

- Backend принимает заявку от retail и дальше сохраняет ее в своем целевом
  контуре: базу, очередь или пайплайн обработки заявок.
- `application_id` можно генерировать последовательно: `ca-000001`,
  `ca-000002`, ...
- `created_at` ставит backend при сохранении.
- История заявок должна быть отдельной от операций клиента.

## Зачем это нужно retail

- Показать клиенту последнюю заявку.
- Дать повторить заявку.
- Показать, что банк помнит обращение клиента.
- Сделать "Персональный лимит" полноценным банковским сценарием, а не разовой
  кнопкой в мобильном приложении.
