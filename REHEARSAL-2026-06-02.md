# Репетиция воркшопа правления — отчёт (2026-06-02)

Прогон провёл организаторский агент по просьбе Виталия: 6 параллельных
агентов = 6 членов правления (2 команды × 3 блока retail/cib/backend),
задача — потребительский кредит, полный цикл до `working` + сценарий
регрессии. По итогам репозитории откатаны на baseline.

## Что прогнали

- **Раунд 1** — 6 ЧП параллельно пишут свой блок, коммит, push в общий main.
- **Краш cib** — деплой cib обеих команд отменён (concurrency, см. находку 1);
  сквозная заявка падала 5xx → −60.
- **Раунд 2** — передеплой cib через `workflow_dispatch` → обе команды `working`,
  20/20, база 500→440→788.
- **Раунд 3** — A ужесточает переводы (currency required, не предупредив retail)
  → регрессия −456; B улучшает объяснение → держится. Табло разошлось: B 727 > A 332.
- **Откат** — force-reset refs на baseline + `workflow_dispatch all` + `/admin/reset`.

## Что работает (провалидировано вживую)

- **Поток коммитов**: 3 участника команды пушат в общий `main`,
  `git pull --rebase --autostash` переставляет работу, конфликтов нет
  (блоки в разных папках).
- **Деплой**: push → GitHub Action → Render Deploy Hook → билд.
- **Симулятор/дашборд**: poll `/health` ловит коммиты, probe 10 критериев,
  LLM-судья (`temperature=0`), формула двигает базу с человеческими reason.
  Наблюдали: +348 (working), −60 (5xx сквозной заявки), −456 (регрессия
  переводов), конкуренцию head-to-head.
- **Координация через CONTRACT.md**: агенты согласовали формат `{decision,
  explanation}` retail↔cib без чтения чужого кода.
- **Различение заявителей** (C6): сильный `c-01394` → approved, слабый
  `c-01434` → rejected у обеих команд.
- **Откат**: refs force-reset + dispatch all + admin/reset вернули чистый baseline.

## Находки и риски для завтра (по приоритету)

### 1. [ВЫСОКИЙ] Deploy workflow теряет средний из быстрых пушей
`.github/workflows/deploy-render.yml`:
```yaml
concurrency:
  group: render-deploy        # одна группа на ВСЕ три блока
  cancel-in-progress: false
```
При `cancel-in-progress: false` GitHub держит в очереди только ОДИН pending
ран. Три push за ~6 c: backend пошёл выполняться, cib встал в очередь, retail
вытеснил cib (cancelled). **Средний из близких пушей молча не выезжает.**
Воспроизвелось на обеих командах — cib не задеплоился в Р1.
- Последствие на воркшопе: участник видит «успех» у соседа, а его блок не
  выехал → фича не работает по неочевидной причине.
- **Фикс**: группа per-блок — `group: deploy-${{ github.ref }}-<block>` (через
  отдельный job на блок), либо вынести деплой каждого блока в свой job со своей
  concurrency, либо убрать `concurrency` (риск гонки хуков минимален — хук
  идемпотентен, билдит текущий main).
- **ПОЧИНЕНО 2026-06-02**: workflow переписан на matrix — каждый блок отдельный
  job с группой `render-deploy-${{ github.ref }}-<block>`, `cancel-in-progress: true`.
  Применено в `team-template` + team_1 (`27560ba`) и team_2 (`5958ed7`). Раны
  подтвердили 3 независимых job (backend/cib/retail), блоки не пересобрались
  (изменён только `.github/`). Пуши разных блоков больше не вытесняют друг друга.

### 2. [ВЫСОКИЙ] Целевые пути ручек не сообщены участникам
probe — закрытый список путей: `POST /credit/decide`, `POST /api/credit-apply`,
`POST+GET /credit-applications`, `/products` со словом «кредит», слово «кредит»
в HTML retail. В `CONTRACT.md` участников этих путей нет, `task_01.md` задачу не
детализирует (озвучивается вслух).
- Риск: команда назовёт ручки иначе (`/loan`, `/apply`) → фича работает между
  блоками, но симулятор не засчитает `working` → база не растёт. Демо
  проваливается не из-за кода.
- **Фикс**: дать ведущему «карту приёмки» (точные пути) для устной озвучки,
  либо прописать целевые ручки в `task_01.md` / шаблонных `CONTRACT.md` как
  спецификацию приёмки.
- **Связанное (подтверждено по коду):** judge/probe заточены ИСКЛЮЧИТЕЛЬНО под
  кредит. `ACTIVE_TASK` объявлен в `render.yaml`, но в коде НЕ используется —
  мёртвая переменная, ничего не переключает. `probe.py` дёргает фиксированные
  кредитные пути, `judge.py` — 10 кредитных критериев, ветвления по задаче нет.
  Любая ДРУГАЯ фича (вклад, инвестиции, переводы++) не засчитывается — база
  не вырастет. **Завтрашняя задача обязана быть «потребительский кредит».**
  Сменить задачу = заранее переписать `probe.py` + `judge.py` (не просто env).

### 3. [СРЕДНИЙ] Регрессия базовой функции штрафуется сильнее ожидаемого
Сломанные переводы дали −456, не −120 по таблице: `REGRESSION_COST` плюс обвал
«удобства» рабочей кредитной фичи (сломанная база срезает кредитную ценность).
Не баг — но при объяснении табло правлению стоит знать: одна поломка базовой
функции рушит весь банк.

### 4. [ИНФО] cold-start free-plan → выкат вразнобой
Блоки выезжают в разное время (билд + 20–30 c пробуждение) → симулятор ловит
промежуточные частичные состояния → временные просадки базы перед ростом. Норма,
но на демо база будет «мигать» вниз перед скачком вверх.
